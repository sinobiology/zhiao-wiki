# 从小米到苹果：我用 Codex 把 590 条小米笔记迁移到 iPhone 备忘录

## 核心逻辑
- **普通问答型 AI 更像是在给路线图；Codex 更像是坐到电脑前，真的陪你把路走完。**
- 很多 AI 问答的典型问题：**它能给你一份「像答案的答案」，但到了真实场景里，问题会继续往下裂开。**
- AI 进入日常生活最有意义的样子：不是写几个炫酷 demo，也不是给一堆看似完整的建议，而是**当你真的卡住时，它能在你的电脑上帮你查、帮你装、帮你转、帮你验证，一步步把事情做完。**

## 行业洞察
- **换设备的真实动因是工作方式的变化**：不是被苹果生态种草，而是自从高频使用 AI 工具后发现很多工具在苹果生态里运行得更顺——ChatGPT、Gemini、Codex 在 Mac 和 iPhone 上客户端、网页体验、系统权限、跨设备同步都更接近现在的工作方式；而在安卓生态尤其国内环境下，很多工具的安装、登录、更新和长期使用都要多绕几道弯。**「当 AI 工具开始深度进入日常工作，我对设备生态的要求也变了。」**
- 最麻烦的迁移对象不是照片、通讯录、微信或文件，而是小米「笔记」App——里面有多年零散记录（文章素材、工作备忘、投资笔记、生活计划、账号信息、突然冒出的想法，还有带图片的记录），**东西不大但很私人也很重要**。

## 技术/管理要点
- **先问豆包的教训**：它给出六套方案（小米换机 App、小米云网页导出、跨平台云便签、单条分享、转移到 iOS、浏览器脚本批量抓取），甚至按「简单到批量」排了优先级。但实操即暴露问题——小米云网页已不支持一键批量导出；「转移到 iOS」更适合新机激活时迁移基础数据，不适合几百条笔记；所谓浏览器脚本和控制台代码只是方向，没有可验证的完整流程。**更关键的是它没解决后半段**：导出来怎么导入 Apple 备忘录？带图片的怎么办？Markdown/HTML/TXT/RTFD 哪个 Apple 备忘录更容易吃进去？导入后图片不显示怎么办？
- **第一层：导出**。确认小米笔记不能直接同步进 Apple 备忘录（开小米云同步 + Safari 访问 i.mi.com 只是「继续看小米云里的笔记」）。Codex 找到开源工具 **nogiszd/xiaomi-note-exporter**（桌面应用，登录 Mi Cloud 把笔记导出成 Markdown 并支持图片附件；非官方工具、非浏览器插件，而是 GitHub 开源项目）。
- **第二层：在 Mac 上部署（这个过程本身很有代表性）**。Codex 先检查本机环境发现有 Node.js 但没有 Rust（该项目是 Tauri + Vue + Rust 桌面应用，Mac 端无现成安装包需从源码构建），随后依次：拉取源码 → 安装 Rust/Cargo 工具链 → 安装 npm 依赖 → 构建前端 → 构建 Tauri 桌面应用 → 安装到 /Applications → 启动验证 → 跑测试确认可用。
  - **中间并不顺利**：GitHub Release 最新版主要提供 Windows 安装包（故选择源码构建）；npm 安装依赖时沙箱网络权限报错；Rust 测试第一次跑时因本地 listener 绑定权限问题失败。**Codex 没有停在「可能是权限问题」，而是提升权限重新跑，最后 55 个 Rust 测试全部通过。**
- **导出结果**：选项包括 Domain（如 us.i.mi.com）、是否把每条笔记单独存成文件、创建时间格式、是否导出图片附件。最终导出 590 条 Markdown 笔记 + images 文件夹。
- **格式适配的三次尝试（核心工程经验）**：
  1. *Markdown → HTML，图片转 base64 内嵌*——浏览器打开完全没问题，**但导入 Apple 备忘录后图片显示为无法查看**。「浏览器支持，不代表 Apple 备忘录导入器支持。」
  2. *HTML + assets 文件夹相对路径引用*——更像普通网页结构，但图片还是看不了。**说明 Apple 备忘录导入 HTML 时并没有把外部图片真正吸进自己的数据库，只导入了文本和一个失效的图片引用。**
  3. *改用 macOS 原生 RTFD*——RTFD 是富文本包格式（不是单文件，包内可同时含 TXT.rtf 和图片附件），**天生适合「富文本 + 图片」，比 HTML 更接近 Apple 备忘录的导入逻辑**。先用系统工具 textutil 测一条带图笔记确认可行，但**又发现新坑：textutil 对多图笔记处理不好，有些只保留一张图**。于是 Codex 写了直接生成 RTFD 的脚本（不依赖 textutil 自动转换）：每条 Markdown 生成一个 .rtfd 包 → 文本写入 TXT.rtf → 每张图片复制成独立附件 → RTF 里逐个引用 → 多图笔记保留多张图。
  - 最终结果：590 条笔记、108 张图片附件、68 条含图笔记、多图笔记也保留多张图。Codex 还做了 **round-trip 检查**——用 macOS 系统工具把生成的 RTFD 反向转回 HTML，确认系统能识别 image_001.jpg、image_002.jpg 等附件。
- **问题被拆成的五层**：小米笔记怎么导出 → Mac 上怎么运行这个工具 → Apple 备忘录能不能直接导 Markdown（不理想）→ HTML 图片能不能导入（不稳定，base64 和相对路径都不行）→ 什么格式更适合（RTFD，因为能把图片作为附件装进同一个包）。**「这些不是一句『用脚本导出』就能解决的。真正有价值的是：每遇到一个失败，Codex 都能继续检查文件、改脚本、重新生成、再验证。」**
- **协作模式的差别**：用户只需不断描述现象（「这个项目帮我部署一下」「导出的 Markdown 怎么进 Apple 备忘录」「图片导入以后看不了」「还有没有别的格式」），Codex 会检查文件、写脚本、跑转换、验证数量、发现图片缺失、继续改方案。**「它不是神奇地『一次回答正确』，而是能陪你把一个真实问题一步步做穿。」**
- **给后来人的操作建议**：先开小米云笔记同步确保笔记在 Mi Cloud → 用 Xiaomi Note Exporter 批量导出（不要手工一条条复制）→ 仅自己备份则 Markdown 足够 → 要导入 Apple 备忘录尤其带图笔记**不要优先用 HTML** → 更稳的路线是转 RTFD → **一定要先测试一两条带图片的笔记再批量导入**，否则发现格式不对还要清理重复笔记。
