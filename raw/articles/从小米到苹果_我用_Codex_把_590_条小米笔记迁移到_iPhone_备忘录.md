从小米到苹果：我用 Codex 把 590 条小米笔记迁移到 iPhone 备忘录

文/知奥

  

最近我做了一个有点大的设备切换：手机从小米换成了 iPhone，电脑也从华为换成了 Mac。

原因不是单纯想换手机，也不是突然被苹果生态种草。

真正的原因是：自从开始高频使用 AI 工具以后，我越来越明显地感觉到，很多 AI 工具在苹果生态里运行得更顺。

比如 ChatGPT、Gemini、Codex 这些工具，在 Mac 和 iPhone 上都可以更稳定地使用。它们的客户端、网页体验、系统权限、跨设备同步，都更接近我现在的工作方式。

而在安卓生态里，尤其是在国内环境下，很多工具的安装、登录、更新和长期使用都会多绕几道弯。有些 App 不好装，有些服务不稳定，有些功能要靠各种替代方案。

所以我开始全面转向苹果生态。

但真正开始换设备以后，我才发现最麻烦的不是照片、通讯录、微信，也不是文件。

最麻烦的是小米手机里那个看起来很普通的「笔记」App。

它里面有我很多年的零散记录：文章素材、工作备忘、投资笔记、生活计划、账号信息、突然冒出来的想法，还有一些带图片的记录。

这些东西不大，但很私人，也很重要。

问题来了：小米笔记怎么迁移到 iPhone 的 Apple 备忘录？

一、先问豆包：答案看起来完整，但没有落地
--------------------

我一开始不是直接找 Codex，而是先问了豆包。

我问的是：

小米便签如何导入苹果手机？

豆包给了我一套看起来很完整的方案：

1\. 小米换机 App  
2\. 小米云网页导出  
3\. 跨平台云便签  
4\. 单条分享  
5\. 转移到 iOS  
6\. 浏览器脚本批量抓取小米云笔记

这些答案乍一看很全面，甚至还按“简单到批量”排了优先级。

但真正操作时，很快就发现问题。

小米云网页现在已经不支持一键批量导出。转移到 iOS 更适合新 iPhone 激活时迁移基础数据，不适合解决几百条笔记的完整迁移。所谓浏览器脚本和控制台代码，也只是一个方向，并没有给出可以直接验证的完整流程。

更关键的是，豆包没有真正解决后半段问题：

导出来以后，怎么导入 Apple 备忘录？

带图片的笔记怎么办？

Markdown、HTML、TXT、RTFD 这些格式，哪个 Apple 备忘录更容易吃进去？

导入以后图片不显示怎么办？

这也是很多 AI 问答的典型问题：它能给你一份“像答案的答案”，但到了真实场景里，问题会继续往下裂开。

后来我换成 ChatGPT + Codex 继续处理。区别一下子就出来了。

普通问答型 AI 更像是在给路线图；Codex 更像是坐到电脑前，真的陪你把路走完。

![](https://mmbiz.qpic.cn/mmbiz_png/a3jlfa2zsXL4tSEiblmOlC6V7WGZvC6icJQHXZlQSJIFHw1w2KTRJSkNUX0QYmTxt5GLJoVQGic1EmYHfc9VqAS7vpcicudLOJRjgzibBRu0RBSQ/640?wx_fmt=png&from=appmsg)

二、先把小米笔记从封闭 App 里导出来
--------------------

第一步是确认：小米笔记不能直接同步进 Apple 备忘录。

如果只是想在 iPhone 上继续查看，可以打开小米云同步，然后用 iPhone 的 Safari 访问 i.mi.com 登录小米账号。

但这只是“继续看小米云里的笔记”，不是迁移到 Apple 备忘录。

我真正想要的是：把笔记变成普通文件，然后进入苹果生态。

Codex 帮我找到了一个开源工具：

nogiszd/xiaomi-note-exporter

这是一个桌面应用，可以登录 Mi Cloud，把小米笔记导出成 Markdown 文件，并支持图片附件。

它不是小米官方工具，也不是浏览器插件，而是一个 GitHub 上的开源项目。对于我这种几百条笔记的情况，它比手工复制靠谱得多。

![](https://mmbiz.qpic.cn/mmbiz_png/a3jlfa2zsXKP7hVVPPHeq3kFWUYvsVtib5cdhQwP8icV5WeGeSO1fHXJSEdpWSobPoRbicmibXVaUjB6wMuAmAWibb9fOKX5Qw6SLl3SATMw5Zbo/640?wx_fmt=png&from=appmsg)

三、让 Codex 在 Mac 上部署 Xiaomi Note Exporter
----------------------------------------

我把 GitHub 项目发给 Codex，让它帮我部署。

这个过程本身就很有代表性。

Codex 先检查本机环境，发现 Node.js 已经有了，但 Rust 没有。这个项目是 Tauri + Vue + Rust 写的桌面应用，所以如果 Mac 端没有现成安装包，就需要从源码构建。

它接着做了几件事：

1\. 拉取 GitHub 项目源码  
2\. 安装 Rust / Cargo 工具链  
3\. 安装 npm 依赖  
4\. 构建前端  
5\. 构建 Tauri 桌面应用  
6\. 安装到 /Applications  
7\. 启动验证  
8\. 跑测试确认项目可用

中间也不是完全顺利。

比如 GitHub Release 里最新版本主要提供的是 Windows 安装包，Mac 上没有现成 dmg。于是 Codex 选择从源码构建。

npm 安装依赖时，沙箱网络权限也报过错。Rust 测试第一次跑时，因为本地 listener 绑定权限问题失败。Codex 没有停在“可能是权限问题”，而是提升权限重新跑，最后 55 个 Rust 测试全部通过。

最终，Xiaomi Note Exporter 成功安装到了 Mac 上：

/Applications/Xiaomi Note Exporter.app

我打开以后，看到的就是这张界面。

![Xiaomi Note Exporter 导出界面](https://mmbiz.qpic.cn/mmbiz_png/a3jlfa2zsXKkmREPeDpVk0j1tZrXfpOpLMAic8h1lpgC1nahO17LoQem6etmJiaK92bghjdjp2TZvorIoUFCiaiaeFd597pPJrb1leHZTyuynjI/640?from=appmsg)

四、导出 590 条小米笔记
--------------

Xiaomi Note Exporter 的界面很简单。

核心选项包括：

1\. Domain：小米云域名，例如 us.i.mi.com  
2\. Split notes into files：是否把每条笔记单独保存成文件  
3\. Created date format：创建时间格式  
4\. Export embedded images：是否导出图片附件

我选择了导出图片，并把笔记拆成单独文件。

最终，所有笔记导出到了这个目录：

/Users/zhiaozhao/Documents/Xiaomi Note Exporter

里面有 590 条 Markdown 笔记，还有一个 images 文件夹保存图片。

到这里，小米笔记已经从小米 App 里出来了。

但新的问题出现了：Apple 备忘录并不直接喜欢 Markdown。

五、第一次尝试：Markdown 转 HTML
-----------------------

Apple 备忘录可以导入一些文件格式。为了让它更容易识别，我让 Codex 写了一个批量转换脚本，把 Markdown 转成 HTML。

这个脚本做了几件事：

1\. 读取所有 .md 文件  
2\. 解析标题、段落、列表、引用、代码块  
3\. 把图片引用转成 HTML 图片  
4\. 每条笔记生成一个独立 HTML 文件  
5\. 生成一个 index.html 索引页

第一版脚本把图片直接转成 base64，内嵌在 HTML 里。

浏览器打开完全没问题。

但导入 Apple 备忘录以后，图片显示为无法查看。

这一步很真实：浏览器支持，不代表 Apple 备忘录导入器支持。

六、第二次尝试：HTML + assets 图片文件
--------------------------

于是 Codex 修改脚本，不再把图片写成 base64，而是把图片放进 assets 文件夹，HTML 里用普通相对路径引用。

也就是：

assets/note\_img\_xxx.jpg

这更像普通网页结构。

但导入 Apple 备忘录后，图片还是看不了。

这说明 Apple 备忘录在导入 HTML 时，并没有把外部图片真正吸进自己的数据库。它只是导入了文本和一个失效的图片引用。

七、第三次尝试：改用 RTFD
---------------

最后，Codex 换了一条路线：不用 HTML，改用 macOS 原生的 RTFD。

RTFD 是 macOS 的富文本包格式。它不是一个单文件，而是一个包，里面可以同时包含：

1\. TXT.rtf  
2\. 图片附件

这个格式天生就适合保存“富文本 + 图片”，比 HTML 更接近 Apple 备忘录的导入逻辑。

Codex 先用系统工具 textutil 测了一条带图片的笔记，确认可以生成 .rtfd 包，里面确实包含图片附件。

但很快又发现一个新坑：textutil 对多图笔记处理不好。有些多图笔记只保留了一张图片。

于是 Codex 又写了一个直接生成 RTFD 的脚本，不再依赖 textutil 自动转换。

这个脚本直接从原始 Markdown 读取内容：

1\. 每条 Markdown 生成一个 .rtfd 包  
2\. 文本写入 TXT.rtf  
3\. 每张图片复制成独立附件  
4\. RTF 里逐个引用图片附件  
5\. 多图笔记保留多张图片

最终检查结果是：

1\. 590 条笔记  
2\. 108 张图片附件  
3\. 68 条笔记包含图片  
4\. 多图笔记也保留多张图

Codex 还做了一个 round-trip 检查：用 macOS 系统工具把生成的 RTFD 反向转回 HTML，确认系统能识别里面的 image\_001.jpg、image\_002.jpg 等图片附件。

这一步之后，最终导入目录变成：

apple\_notes\_rtfd\_latest

这才是更适合拿去导入 Apple 备忘录的版本。

八、这次协作真正解决的是什么
--------------

表面上看，这件事只是“小米笔记导入 iPhone 备忘录”。

但实际过程里，问题被拆成了很多层。

第一层：小米笔记怎么导出？

答案是用开源工具 Xiaomi Note Exporter，从 Mi Cloud 抓取笔记，导出 Markdown 和图片。

第二层：Mac 上怎么运行这个工具？

答案是让 Codex 从源码部署 Tauri 应用，补齐 Rust 和 npm 依赖，完成构建和验证。

第三层：Apple 备忘录能不能直接导 Markdown？

不理想，所以转 HTML。

第四层：HTML 图片能不能导入？

不稳定。base64 不行，相对路径也不行。

第五层：什么格式更适合 Apple 备忘录？

RTFD。因为它能把图片作为附件装进同一个包里。

这些不是一句“用脚本导出”就能解决的。

真正有价值的是：每遇到一个失败，Codex 都能继续检查文件、改脚本、重新生成、再验证。

九、我对 Codex 的感觉
--------------

以前我遇到这种问题，大概率会这样：

1\. 搜索半天，看到几个 GitHub 项目  
2\. 不知道哪个还能用  
3\. 装依赖报错  
4\. Mac 上构建失败  
5\. 导出后格式不对  
6\. 导入后图片丢失  
7\. 最后放弃，只手工复制最重要的几十条

这次不一样。

我只需要不断描述现象：

这个项目帮我部署一下。

导出的 Markdown 怎么进 Apple 备忘录？

图片导入以后看不了。

还有没有别的格式？

Codex 会检查文件、写脚本、跑转换、验证数量、发现图片缺失，再继续改方案。

它不是神奇地“一次回答正确”，而是能陪你把一个真实问题一步步做穿。

这对我来说，比单纯生成一段漂亮答案更重要。

十、给后来人的建议
---------

如果你也想从小米笔记迁移到 iPhone，我建议这样做：

先打开小米云笔记同步，确保笔记已经在 Mi Cloud。

然后用 Xiaomi Note Exporter 批量导出，不要手工一条条复制。

如果只是自己备份，Markdown 就够了。

如果要导入 Apple 备忘录，尤其是带图片的笔记，不要优先用 HTML。

HTML 在浏览器里看起来正常，但导入 Apple 备忘录后，图片可能不可见。

更稳的路线是转成 RTFD，再导入 Apple 备忘录。

最后，一定要先测试一两条带图片的笔记，再批量导入。不要上来就把几百条全部导进去，否则发现格式不对，还要清理重复笔记。

十一、结尾
-----

这次换设备，本来只是从小米手机换到 iPhone，从华为电脑换到 Mac。

但它背后其实是工作方式的变化。

当 AI 工具开始深度进入日常工作，我对设备生态的要求也变了。哪个生态更适合安装、运行、同步、调用这些工具，哪个生态就更适合我现在的工作流。

小米笔记迁移只是这个变化里冒出来的一个具体问题。

但也正是这种具体问题，最能体现 AI 工具的真实价值。

不是写几个炫酷 demo，也不是给一堆看似完整的建议。

而是当你真的卡住时，它能在你的电脑上帮你查、帮你装、帮你转、帮你验证，一步步把事情做完。

对我来说，这就是 AI 进入日常生活最有意义的样子。
