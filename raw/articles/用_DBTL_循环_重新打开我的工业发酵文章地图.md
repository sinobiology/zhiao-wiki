用 DBTL 循环，重新打开我的工业发酵文章地图
========================

文/知奥
====

![](https://mmbiz.qpic.cn/sz_mmbiz_png/a3jlfa2zsXL5U2CYXicWhevWCELG5b30YIlx2TAxWxAA9ErLibdV7XwvF2d1RHkhQj1O4B7a96HbKPVZrmdOe64Yx3gqLLUa0MDyUUVtibOxbs/640?wx_fmt=png&from=appmsg)

如果用一句话概括合成生物学，很多人会说：它是在用工程学方法改写生命。

但如果再往下追问：工程学方法到底是什么？

最经典的答案，是 DBTL 循环。

D，Design，设计。先提出假设，设计路线，确定靶点和系统架构。

B，Build，构建。把设计落到菌株、载体、培养基、设备和工艺系统里。

T，Test，测试。用实验、发酵批次、过程数据和现场异常来检验它是不是真的有效。

L，Learn，学习。把数据、失败、成本、市场和产业反馈重新吸收，形成下一轮设计。

这四个字母看起来像实验室里的方法论，但我越写工业发酵，越发现它其实也是理解我整个公众号专业文章的一把钥匙。

因为工业发酵里的 DBTL，不只发生在细胞里。

它发生在基因组里，发生在发酵罐里，发生在中控室里，发生在财务报表里，也发生在价格战、专利战和全球供应链里。

过去我写过很多篇文章：有的讲基因编辑，有的讲发酵罐，有的讲染菌，有的讲赖氨酸战争，有的讲味之素百年史，有的讲氨基酸行业周期。单篇看，每一篇都像一个局部切片；但如果把它们放进 DBTL 循环里，它们就不再散乱，而是连成了一张图。

这篇文章，就是这张图。

* * *

一、Design：先设计一座细胞工厂
------------------

![](https://mmbiz.qpic.cn/sz_mmbiz_png/a3jlfa2zsXKic0o4D0EY0QDl1U4iaJAUpCIGx8MKyPE57P7RiccH8lu43vC7veO3icY9D78dj6er6gIzC0YmZicnyAkMzibCVWZ0ykJP3icrsZPmTg/640?wx_fmt=png&from=appmsg)

  

DBTL 的第一步是 Design。

在合成生物学里，设计通常意味着：我要生产什么分子？用什么底盘细胞？改哪条代谢通路？敲除什么、过表达什么、调控什么、外排什么？

但在工业发酵里，Design 不能只停在基因图谱上。一个真正有效的设计，至少要同时回答三类问题：

第一，细胞内部的代谢逻辑是什么？

第二，细胞外部的工程环境是什么？

第三，这条路线最后能不能落到成本曲线上？

所以，如果新读者第一次进入我的专业文章体系，我建议从这组文章开始。

这些文章共同回答一个问题：

我们到底是在设计什么？

表面上看，是设计一株菌。

更准确地说，是设计一种“细胞愿意持续工作的工业生态”。

早期的“进、通、节、堵、出”，是在设计代谢物流；后来的动态调控，是在设计时间节奏；抗压育种，是在设计细胞面对大罐环境时的承受能力；合成成瘾、固定化和进化鲁棒底盘，是在设计细胞群体的博弈规则。

这就是我为什么越来越觉得，工业发酵里的 Design，不是画一条通路，而是写一套规则。

二、Build：把想法落到菌株、罐体、空气、蒸汽和管道里
----------------------------

![](https://mmbiz.qpic.cn/sz_mmbiz_png/a3jlfa2zsXIiasJmdH9nVsYstFABxQzOlhhdibIqUZoGGaxaz85S2Cg7tvs3FCKvCJFXyQTJicnO7mapnMCCJ3ae1cr9OCBearDzrJJxpWxD8s/640?wx_fmt=png&from=appmsg)

  

设计再漂亮，也必须进入 Build。

在实验室语境里，Build 通常指构建菌株：做载体、转化、编辑、筛选、验证。

但工业发酵里的 Build 要宽得多。

你要构建的不只是一个基因型，还包括种子系统、无菌空气系统、压缩空气系统、搅拌传质系统、温控系统、灭菌系统、补料系统、取样系统、DCS 控制系统，以及让这一切长期稳定运行的工程秩序。

这一组文章想表达的核心很简单：

Build 不是“把设计做出来”这么轻描淡写。

Build 是把生命放进工业环境里，并且为它搭一套能活、能长、能产、能稳定复制的外部世界。

如果说 Design 是在脑子里设计细胞工厂，那么 Build 就是把这座工厂接上水、电、汽、风、糖、氨、碱、油，让它真正开工。

三、Test：让数据、批次和事故告诉我们，设计到底成不成立
-----------------------------

![](https://mmbiz.qpic.cn/mmbiz_png/a3jlfa2zsXJE0BcvJvYrsVXVx0n1Za467OJONvYZor0ia3tSC8kCiaPCllAb90LHOf9PjP6NM00yuIuZnF1VBwiaiaWdBoIEMof9BGibpbibqlnd0/640?wx_fmt=png&from=appmsg)

  

DBTL 的第三步是 Test。

测试不是简单地测一个产量、一个 OD、一个转化率。

在工业发酵里，Test 是一整套残酷的现实拷问：

小试好，5L 好不好？

5L 好，50L 好不好？

50L 好，500 吨好不好？

这批好，下一批好不好？

白天好，夜班好不好？

新员工操作好不好？

原料波动时好不好？

夏天冷却能力不足时好不好？

一旦进入真实生产，所有设计都会被大罐、设备、人员、环境和时间重新审判。

Test 这一环最容易被低估。

因为很多人以为“测试”只是验证设计是否正确。但在工业发酵里，Test 往往会反过来暴露我们根本没有设计到的问题。

摇瓶里没有混合死区，工业罐里有。

实验室里没有吨级补料延迟，工业罐里有。

小罐里温度容易压住，大罐里热量像一座内部自燃的锅炉。

论文里的菌株没有夜班员工，工厂里的菌株有。

所以 Test 的真正价值，不只是给 Design 打分，而是发现 Design 视野之外的变量。

五、把四步连起来：这不是四个栏目，而是一台发动机
------------------------

如果只把 DBTL 当成四个分类标签，那就太浅了。

它真正的力量，在于循环。

Design 不是凭空设计，而是 Learn 之后的新假设。

Build 不是机械执行，而是把设计翻译成可运行系统。

Test 不是验收表格，而是让真实世界用数据和事故说话。

Learn 不是写总结，而是把失败和反馈转化成下一轮更好的 Design。

用这套框架回看我的公众号专业文章，你会发现它们大致形成了四层循环：

第一层，是细胞内循环：代谢网络、基因编辑、动态调控、底盘工程。

第二层，是发酵罐循环：空气、搅拌、温度、灭菌、补料、放大和过程控制。

第三层，是工厂经营循环：单耗、能耗、产能利用率、固定成本分摊和组织能力。

第四层，是产业竞争循环：价格战、专利战、贸易救济、全球供应链和行业周期。

这四层不是并列的。

细胞内循环决定产品能不能出来。

发酵罐循环决定产品能不能稳定出来。

工厂经营循环决定产品能不能便宜出来。

产业竞争循环决定企业能不能长期活下来。

这就是我理解的工业发酵：

它不是一个大罐子，也不是一条代谢通路。

它是一套把生命活动、工程系统、成本曲线和产业竞争绑在一起的复杂循环。

结语：我真正想写的，是一部工业发酵的进化史
---------------------

回头看，我写这些文章时，并不是一开始就想好了 DBTL 框架。

很多文章，是被现场经验推着写出来的；很多文章，是被行业事件刺激出来的；还有很多文章，是为了把一个自己终于想明白的问题讲给更多人听。

但当这些文章积累到一定数量后，它们开始显露出一个共同主题：

工业发酵不是一次性工程，而是一套永不停转的学习系统。

每一代菌株，都是上一轮失败后的 Design。

每一套发酵系统，都是无数次 Build 的工程沉淀。

每一个批次数据，都是 Test 给出的真实反馈。

每一轮价格战、专利战和产业周期，都是 Learn 逼出来的新认知。

所以，DBTL 不只是合成生物学的方法论。

它也是我这个公众号专业文章的底层结构。

我希望读者通过这篇总纲文章，不再把这些文章看成一篇篇孤立的技术科普、行业复盘或个人感悟，而是把它们看成同一个循环里的不同节点。

从细胞开始，到发酵罐，到工厂，到产业。

从 Design 开始，Build 出来，Test 验证，再 Learn 回去。

生命被工程化，工程被产业化，产业又反过来逼迫生命重新被设计。
