# 增产为什么也要隐瞒？

## 核心逻辑
- **正向作弊的可怕之处：它披着好消息的外衣，所以没有人愿意查。** 坏消息会触发警报，好消息只会触发掌声——而掌声是世界上最有效的掩护。
- **组织最大的认知漏洞，不是相信坏消息，而是默认好消息不需要验证。** 真正成熟的组织，不仅审计失败，也审计成功。
- 员工选择隐瞒不是因为他们不诚信，而是**因为制度让诚实变成了一件吃亏的事**。

## 技术/管理要点
- **事件本身**：某部门推行新菌种后产量较计划出现可观提升——本该是好消息。但为了保证后续检修不欠产、保订单完美率，部门安排车间按计划产量录入系统，把多出来的产品「藏」在库房；截至被发现时累计已有相当数量产品未录入系统，部分甚至已违规喷码。从车间到分管领导相关责任人均受处理，但通报里有一句话特别刺眼：「本次事件虽未给公司造成损失。」
- **诚信的不对称性**：人天然会根据结果判断行为——结果好就觉得行为没那么严重。但**行为的对错不该由结果来定义**：如果一个人闯了红灯恰好没撞到人，你会觉得他不算闯红灯吗？如果偷了东西恰好没被发现，你会觉得他不算偷吗？
- **为什么正向隐瞒更危险**：员工隐瞒事故、失败、废品当然严重，但**至少组织对这种隐瞒是有警惕的**（审计会查、品管会追、出了事大家都紧张，因为坏消息天然触发警报）。而藏增产——多出来的产品躺在库房里，没有人受伤、没有客户投诉、没有财务报表上的红字，所有人看到「超额完成」第一反应是高兴，**没有人愿意去追一个好消息**。
- **同类的「正向作弊」清单**：少报成本（数字漂亮，没人追问）、提前确认收入（业绩好看，谁会质疑）、隐藏库存（账面平衡，皆大欢喜）、提前完成指标（领导满意，团队轻松）——所有这些都是「为了让数字更漂亮」，因为数字漂亮所以没人愿意深究。
- **对「没造成损失何必上纲上线」的回应**：真正的问题不是增产（增产是好事，没人否认），而是**组织还能不能相信自己的数据**。一旦允许「好的修饰」，就没有理由禁止「坏的修饰」——**你打开的不是一个口子，而是一扇门**：好坏修饰的界限会越来越模糊，直到有一天你分不清哪些数字是真的。处罚这批人不是为了惩罚增产，而是为了守住一条底线：数据必须真实，不管结果是好是坏。
- **诚信不能是结果主义的遮羞布**：亏了隐瞒是欺骗；赚了隐瞒同样是欺骗——**欺骗的是组织的决策系统，欺骗的是管理的透明度**。一旦开了「结果好就可以轻罚」的口子，道与德就被架空了，利与害成了实质上的裁判标准。组织是利益交织的系统，「没出事」三个字会同时让很多人松一口气（当事人、主管，甚至审计的人）。
- **根源在考核机制（「鞭打快牛」）**：说真话的代价是明年指标加码，隐瞒的代价是绩效扣分。**当制度本身在奖励修饰、惩罚真实的时候，你不能只要求员工「要诚实」——不能一边设计了一个让诚实吃亏的系统，一边用道德大棒去打那些被系统逼得不诚实的人。**
- **处罚只是止损，真正重要的是让真实比漂亮更有价值**。要从考核机制开始追问：指标是不是只升不降的棘轮？预算逻辑有没有给「如实上报」留出空间？汇报文化里，报忧的人是不是比报喜的人更容易被边缘化？
- **给普通工程师/班组长/数据录入员的检验方法**：看到一组「完美」的数据（没有波动、没有异常、一切恰好达标），先问自己——**这个结果如果不好，还会被如实上报吗？** 如果答案是「不会」，这组数据就值得警惕。**真正的好数据从来不是平平整整的**：发酵罐里的溶氧会跳，pH 会抖，收率会波动。**真实的数据有呼吸感，修饰过的数据才「完美」。**
